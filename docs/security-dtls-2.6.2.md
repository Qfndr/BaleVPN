# اصلاح امنیتی DTLS/WebRTC — نسخهٔ ۲٫۶٫۲

آسیب‌پذیری `RUSTSEC-2026-0387` مربوط به تفاوت زمانی برخی عملیات محاسباتی `crypto-bigint` بود. نسخهٔ قدیمی ۰٫۵٫۵ از مسیر `webrtc-dtls → p256/p384 → elliptic-curve` در برنامهٔ دسکتاپ، سرور و کتابخانهٔ JNI اندروید وارد می‌شد.

در این نسخه، زنجیرهٔ منحنی‌های RustCrypto به نسخه‌های upstream جدید منتقل شده و `crypto-bigint` روی ۰٫۷٫۷، بالاتر از حداقل اصلاح‌شدهٔ ۰٫۷٫۶، قفل شده است. `ctutils` نیز روی نسخهٔ اصلاح‌شدهٔ ۰٫۴٫۵ قرار دارد. برای سازگاری با WebRTC موجود، تغییر محدودی روی سورس منتشرشدهٔ DTLS اعمال شده است؛ محاسبات رمزنگاری جدیدی در خود پروژه نوشته نشده‌اند. مشخصات منبع، مجوزها و تغییرات در `vendor/README.md` و `vendor/webrtc-dtls/UPSTREAM.json` موجود است.

این اصلاح قالب DTLS، cipher suiteها، احراز هویت، هویت ذخیره‌شدهٔ دستگاه یا رمزگذاری QUIC داخل تونل را تغییر نمی‌دهد. ارتقا نیازمند حذف پوشهٔ داده، ورود تازه یا تعویض کلید جفت‌سازی نیست. بعد از توقف نسخهٔ قبلی، فایل اجرایی جدید را با همان پوشهٔ داده اجرا کنید.

تست‌های تطبیق P-256 و P-384 با `ring`، ردکردن نقاط نامعتبر، تکرار مشتق‌سازی برای ارسال مجدد دست‌دهی، و تست‌های اصلی DTLS اجرا می‌شوند. علاوه بر cargo-audit، گیت مستقل پروژه ورود دوبارهٔ نسخه‌های آسیب‌پذیر به lockfileها را رد می‌کند. ساخت اندروید هم از lockfile قفل‌شده استفاده می‌کند. این بررسی‌ها تضمین نبودن همهٔ آسیب‌پذیری‌های ناشناخته یا تأیید سرویس زندهٔ بله نیستند.

برای دریافت نسخهٔ صحیح، فایل `build-info.json` و هش‌های `SHA256SUMS.txt` بسته را بررسی کنید. فایل‌های قدیمی روی دستگاه‌ها خودکار اصلاح نمی‌شوند. رلیز شامل بسته‌های گرافیکی و headless ویندوز/لینوکس/مک و APK اندروید است؛ بستهٔ مک Developer ID و notarization اپل ندارد. گزارش‌های امنیتی و منشأ بیلدها همراه رلیز منتشر می‌شوند.
