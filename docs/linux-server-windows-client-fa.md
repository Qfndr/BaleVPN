# راهنمای کامل سرور لینوکس و کلاینت ویندوز

اگر می‌خواهید **خود لینوکس نقش کلاینت داشته باشد**، [راهنمای اجرای کلاینت روی سرور لینوکس](linux-client-fa.md) را بخوانید. نقش برنامه با انتخاب یا فرمان تعیین می‌شود، نه با سیستم‌عامل.

> نسخهٔ آزمایشی ۲٫۲ به جفت‌سازی کلید عمومی دو سمت نیاز دارد. پیش از اتصال، [راهنمای امنیت و ارتقا](secure-pairing-fa.md) را بخوانید.


این راهنما برای سناریوی «سرور خارج از کشور با اینترنت قابل دسترس و کلاینت روی ویندوز» است. دستورهای سرور با فرض مسیر `/root/balevpn` و ورود با کاربر `root` نوشته شده‌اند. برای شروع از `userspace NAT` استفاده می‌کنیم؛ به تنظیم TUN، IP forwarding یا قواعد NAT دستی نیاز ندارد.

## مسیر اتصال و معنی وضعیت‌ها

```text
برنامهٔ ویندوز با تنظیم SOCKS5
          ↓
کلاینت BaleVPN روی 127.0.0.1:1080
          ↓
تونل روی زیرساخت تماس بله
          ↓
سرور BaleVPN روی لینوکس خارج از کشور
          ↓
اینترنت، با IP خروجی سرور
```

بله حامل ارتباط بین دو حساب است؛ اتصال نهایی به سایت‌ها را سرور لینوکس برقرار می‌کند. داده‌ها به‌شکل پیام متنی یا فایل در چت بله ارسال نمی‌شوند. عبور از زیرساخت بله تضمین تعرفهٔ داخلی یا اینترنت رایگان نیست.

**در ویندوز، نسخهٔ فعلی پراکسی SOCKS5 فراهم می‌کند؛ تمام ترافیک سیستم خودکار وارد تونل نمی‌شود.** فقط برنامه‌هایی که روی این پراکسی تنظیم شده‌اند از آن استفاده می‌کنند. قابلیت `--client-tun` مخصوص لینوکس و مک است.

| وضعیت | معنی |
| --- | --- |
| `WebSocket connected` | ورود و ارتباط کنترلی با بله برقرار است؛ هنوز اثبات اتصال تونل اینترنت نیست. |
| `Connecting to server…` | کلاینت در حال برقراری تونل است. |
| `Waiting for server to pick up…` | سمت سرور و درخواست پذیرش را بررسی کنید. |
| `Server — waiting for clients…` | سرور آماده است و هنوز کلاینتی متصل نشده است. |
| `SOCKS5 on 127.0.0.1:1080 …` | پراکسی تونل در کلاینت آماده شده؛ مرحلهٔ بعد آزمون درخواست واقعی از طریق آن است. |

## ۱. پیش‌نیازها و انتخاب فایل درست

- سرور باید به اینترنت و سرویس‌های بله دسترسی خروجی داشته باشد.
- از **دو حساب بلهٔ متفاوت** استفاده کنید: یکی برای سرور و دیگری برای کلاینت ویندوز.
- باینری لینوکس را به سرور و باینری ویندوز را به کامپیوتر خود منتقل کنید؛ فایل `.exe` روی لینوکس اجرا نمی‌شود.
- معماری فایل باید با سرور تطبیق داشته باشد. خروجی `x86_64` روی سرور ARM اجرا نمی‌شود.
- برای سرور، خروجی **headless** را انتخاب کنید تا به GTK/WebKit و محیط دسکتاپ نیاز نباشد.
- بستهٔ تست لینوکس GNU ساخته‌شده برای این سناریو به glibc نسخهٔ 2.36 یا جدیدتر نیاز دارد؛ مانند Debian 12 یا Ubuntu 24.04. این حداقل را به همهٔ بیلدهای احتمالی تعمیم ندهید.

شمارهٔ نسخه، مثلاً `2.1.5`، به‌تنهایی برای تشخیص بسته کافی نیست؛ بیلدهای تست متفاوت ممکن است شمارهٔ یکسان داشته باشند. اگر `build-info.json` یا `BUILD-*.txt` همراه بسته است، شناسهٔ `source_commit` را هم بررسی کنید. تغییر کد `main` فایل ریلیزهای قدیمی یا نسخه‌ای را که قبلاً دانلود کرده‌اید تغییر نمی‌دهد؛ برای اصلاحات جدید، باینری یا artifact مربوط به کد اصلاح‌شده را تهیه کنید.

**در ترمینال سرور:**

```bash
cd /root/balevpn
ls -la
uname -m
ldd --version
chmod +x ./bale-vpn
./bale-vpn --version
```

اگر بسته فایل checksum دارد، از همان پوشه بررسی کنید:

```bash
sha256sum -c SHA256SUMS.txt
```

فایل `bale-vpn` باید مستقیماً در این پوشه باشد. اگر بسته پوشهٔ `Linux-x64` ساخته، ابتدا وارد همان پوشه شوید یا فایل‌های برنامه را به مسیر موردنظر منتقل کنید. بسته را مرتب داخل پوشهٔ استخراج‌شدهٔ قبلی استخراج نکنید؛ ممکن است چند پوشهٔ تودرتو و چند باینری متفاوت ایجاد شود.

## ۲. پورت‌های مورد استفاده

| کاربرد | آدرس |
| --- | --- |
| پنل مدیریت سرور لینوکس | `127.0.0.1:37127` روی سرور |
| پنل سرور از طریق SSH در مرورگر ویندوز | `http://127.0.0.1:37127` |
| پنل کلاینت ویندوز با دستورهای این راهنما | `http://127.0.0.1:37126` |
| پراکسی اینترنت کلاینت ویندوز | SOCKS5 روی `127.0.0.1:1080` |

پورت مدیریت با پورت پراکسی فرق دارد؛ `37127` پراکسی اینترنت نیست. پیش‌فرض خود باینری برای مدیریت `3001` است؛ این راهنما پورت‌ها را صریح تعیین می‌کند تا دو پنل تداخل نداشته باشند. اگر `Start.vbs` (در بسته‌های قدیمی `Start.cmd`) بستهٔ شما پورت دیگری تعیین می‌کند، نشانی همان اجراکننده را استفاده کنید.

## ۳. اجرای اولیهٔ سرور برای تست

**در ترمینال لینوکس، یک بار اجرا کنید:**

```bash
cd /root/balevpn
chmod +x ./bale-vpn
nohup ./bale-vpn --headless --port 37127 \
  --config-dir /root/balevpn/data \
  server --nat-mode userspace \
  > /root/balevpn/balevpn.log 2>&1 < /dev/null &
echo $! > /root/balevpn/balevpn.pid
```

برنامه با بستن SSH متوقف نمی‌شود، ولی پس از ریبوت خودکار اجرا نمی‌شود. برای اجرای دائمی بخش systemd را انجام دهید. هم‌زمان چند نمونه با یک پوشهٔ تنظیمات اجرا نکنید.

بررسی وضعیت:

```bash
tail -n 30 /root/balevpn/balevpn.log
ss -ltnp 'sport = :37127'
curl --fail http://127.0.0.1:37127/config
```

باید پنل روی loopback گوش دهد و پاسخ `/config` حالت `server` را نشان دهد. ترتیب گزینه‌ها مهم است: گزینه‌های عمومی قبل از ساب‌فرمان `server` و `--nat-mode` بعد از آن. برای اجرای مستقیم باینری از `--mode server` استفاده نکنید؛ آن شکل مربوط به اسکریپت کمکی است.

پوشهٔ `data` در اولین ذخیره ساخته می‌شود. مسیر تنظیمات این نصب:

```text
/root/balevpn/data/.bale-vpn_config.json
```

این فایل حاوی توکن ورود است و نباید در گزارش عمومی مشکل ارسال شود.

## ۴. دسترسی به پنل سرور از ویندوز با SSH

**این دستور در PowerShell ویندوز اجرا می‌شود، نه ترمینال سرور.** به‌جای `SERVER_IP` آی‌پی واقعی سرور را بگذارید:

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:37127:127.0.0.1:37127 root@SERVER_IP
```

اگر پورت SSH متفاوت است، آن را با `-p` مشخص کنید؛ برای نمونه:

```powershell
ssh -p 2222 -N -o ExitOnForwardFailure=yes -L 127.0.0.1:37127:127.0.0.1:37127 root@SERVER_IP
```

اگر نام کاربری SSH دیگری دارید، همان را به‌جای `root` بگذارید. سکوت ترمینال بعد از ورود طبیعی است؛ `-N` فقط انتقال پورت انجام می‌دهد. پنجره را باز نگه دارید و در مرورگر ویندوز باز کنید:

```text
http://127.0.0.1:37127
```

پنل را با IP عمومی سرور باز نکنید. برنامه روی loopback گوش می‌دهد و Host/Origin محلی را بررسی می‌کند. برای این روش نیازی به بازکردن پورت مدیریت در فایروال عمومی نیست. SSH port-forward فقط برای **مدیریت پنل** است؛ ترافیک اینترنت کلاینت از تونل بله می‌رود.

بستن پنجرهٔ port-forward دسترسی مرورگر به پنل سرور را قطع می‌کند؛ سرور اجراشده با nohup یا systemd همچنان کار می‌کند.

## ۵. ورود حساب سرور

در پنل سرور روی `37127`:

1. شمارهٔ حساب **سرور** را وارد کنید؛ با حساب کلاینت ویندوز متفاوت باشد.
2. `Send OTP` را بزنید. کانال دریافت کدی را که برنامه اعلام می‌کند بررسی کنید؛ ممکن است Telegram، بله، SMS یا روش دیگری باشد.
3. تازه‌ترین کد همین درخواست را فقط در برنامه وارد کنید و `Verify` بزنید.
4. اگر برای حساب جدید نام خواسته شد، ثبت‌نام را تکمیل کنید.
5. وضعیت اتصال به بله و پیام انتظار سرور را بررسی کنید. اگر سرور قطع است و دکمهٔ `Connect` نمایش داده می‌شود، آن را بزنید.

نقش با ساب‌فرمان `server` مشخص شده و لازم نیست دوباره آن را از انتخاب‌گر نقش انتخاب کنید. کد مصرف‌شده یا منقضی را در درخواست جدید استفاده نکنید؛ تا پایان شمارش معکوس درخواست مجدد صبر کنید.

## ۶. اجرای کلاینت ویندوز

اگر بسته `Start.vbs` (در بسته‌های قدیمی `Start.cmd`) دارد، آن را اجرا کنید. اگر میان‌بر محلی `Start-BaleVPN.cmd` برای نصب شما ساخته شده، همان را استفاده کنید تا مسیر تنظیمات قبلی حفظ شود. اجرای مستقیم از پوشهٔ فایل ویندوز، در PowerShell:

```powershell
.\BaleVPN.exe --port 37126 --config-dir .\data client
```

برای استفاده از مرورگر به‌جای پنجرهٔ بومی:

```powershell
.\BaleVPN.exe --headless --port 37126 --config-dir .\data client
```

سپس `http://127.0.0.1:37126` را باز کنید و ترمینال برنامه را باز نگه دارید؛ بستن آن اجرای مستقیم را متوقف می‌کند. اگر باینری نام دیگری دارد، نام واقعی را در دستور جایگزین کنید.

با حساب **کلاینت** وارد شوید. پس از ورود باید `Server peer`، `SOCKS5 port`، جست‌وجوی مخاطب و `Connect` دیده شوند. **«Tunnel proxy» عنوان بخش است و نیاز به کلیک ندارد.**

اگر فقط عنوان و Logout دیده می‌شود، ممکن است بستهٔ قدیمی باگ پنهان‌ماندن کنترل‌های Client را داشته باشد. بارگذاری تازهٔ رابط در مرورگر می‌تواند موقتاً کمک کند؛ راه‌حل دائمی بیلد دارای اصلاح رابط است. برای تازه‌کردن صفحه لازم نیست Logout کنید.

## ۷. انتخاب سرور و پذیرش کلاینت

در پنل کلاینت روی `37126`:

1. `Refresh` کنار `Server peer` را بزنید و حساب سرور را انتخاب کنید.
2. اگر در فهرست نیست، شمارهٔ حساب سرور را در `Find peer by phone number` وارد و `Search` را بزنید؛ **نتیجهٔ درست را هم انتخاب کنید**.
3. پورت SOCKS5 را برای شروع `1080` نگه دارید و `Connect` بزنید.

در پنل سرور روی `37127`، بخش `Pending requests` را بررسی کنید:

| دکمه | نتیجه |
| --- | --- |
| `Accept once` | فقط همین اتصال را می‌پذیرد. |
| `Allow always` | حساب کلاینت را مجاز می‌کند تا تماس‌های بعدی خودکار پذیرفته شوند. |
| `Reject` | درخواست را رد و حساب را به فهرست مسدود اضافه می‌کند. |

برای کلاینت شخصی خود، پس از تطبیق حساب، `Allow always` را انتخاب کنید. اگر قبلاً مسدود شده، در `Blocked callers` دکمهٔ `Unblock` را بزنید. درخواست‌های در انتظار مهلت محدود دارند؛ پس از پایان مهلت از کلاینت دوباره اتصال را آغاز کنید.

پیام `SOCKS5 on 127.0.0.1:1080` را در کلاینت بررسی کنید. صرف تغییر دکمه به Disconnect یا سبزشدن WebSocket کافی نیست؛ درخواست واقعی از طریق پراکسی را هم آزمایش کنید.

## ۸. تنظیم SOCKS5 و DNS در ویندوز

برنامهٔ موردنظر باید SOCKS5 را پشتیبانی کند:

| گزینه | مقدار |
| --- | --- |
| نوع پراکسی | SOCKS5 |
| میزبان | `127.0.0.1` |
| پورت | `1080` یا پورت انتخاب‌شده در کلاینت |
| نام کاربری و رمز پراکسی | برای شنوندهٔ محلی پیش‌فرض خالی |
| DNS | از طریق SOCKS / Remote DNS |

برای نمونه در [تنظیمات اتصال Firefox](https://support.mozilla.org/en-US/kb/connection-settings-firefox)، حالت Manual proxy، SOCKS Host و پورت بالا، SOCKS v5 و `Proxy DNS when using SOCKS v5` را انتخاب کنید. برای این آزمون فیلد HTTP Proxy را پر نکنید. اگر تنظیمات مرورگر مدیریت‌شده و قفل است، از برنامه‌ای با تنظیم SOCKS مستقل استفاده کنید.

واردکردن این پورت در تنظیم عمومی HTTP proxy ویندوز، تمام برنامه‌ها را SOCKS5 نمی‌کند. پورت `37126` یا `37127` هم پراکسی اینترنت نیست. عبور همهٔ UDP یا همهٔ برنامه‌های سیستم را فرض نکنید؛ این سناریو را ابتدا با HTTPS روی TCP آزمایش کنید.

**در PowerShell ویندوز:**

```powershell
Test-NetConnection 127.0.0.1 -Port 1080
curl.exe --proxy socks5h://127.0.0.1:1080 --connect-timeout 10 --max-time 30 -I https://example.com
```

از `curl.exe` استفاده کنید تا با alias احتمالی `curl` اشتباه نشود. `socks5h` نام دامنه را از سمت پراکسی resolve می‌کند؛ [راهنمای رسمی curl](https://curl.se/docs/manpage.html#--socks5-hostname) تفاوت آن با SOCKS5 دارای DNS محلی را توضیح می‌دهد. موفق‌بودن Test-NetConnection فقط بازبودن پورت محلی را نشان می‌دهد؛ پاسخ HTTPS از مسیر پراکسی آزمون مهم‌تر است.

برای دیدن IP خروجی، صفحهٔ نمایش IP مورداعتمادتان را در مرورگر پراکسی‌شده باز و با IP خروجی سرور مقایسه کنید. سرور ممکن است پشت NAT باشد؛ IP خروجی الزاماً همان IP اینترفیس داخلی آن نیست.

## ۹. اجرای دائمی با systemd

این بخش برای سرور دارای systemd، مانند نصب‌های معمول Debian/Ubuntu، است. در کانتینر بدون systemd از مدیر پردازش همان محیط استفاده کنید.

ابتدا اجرای nohup را متوقف کنید تا دو نمونه هم‌زمان نداشته باشید. PID ثبت‌شده را با فرمان پردازش تطبیق دهید:

```bash
BALEVPN_PID=$(cat /root/balevpn/balevpn.pid)
ps -p "$BALEVPN_PID" -o pid=,args=
```

فقط اگر همین پردازش BaleVPN با مسیر نصب موردنظر است، آن را متوقف کنید:

```bash
kill -TERM "$BALEVPN_PID"
```

اگر PID وجود ندارد یا متعلق به برنامهٔ دیگری است، از آن استفاده نکنید. با `ss -ltnp 'sport = :37127'` پردازش گوش‌دهنده را شناسایی کنید. اگر از ابتدا systemd را انتخاب کرده‌اید، توقف nohup لازم نیست.

نمونهٔ آمادهٔ مخزن: [balevpn.service](../deploy/systemd/balevpn.service). از ریشهٔ یک checkout نصب کنید:

```bash
sudo install -m 644 deploy/systemd/balevpn.service /etc/systemd/system/balevpn.service
```

اگر فقط باینری روی سرور دارید، فایل را مستقیم بسازید:

```bash
cat > /etc/systemd/system/balevpn.service <<'EOF'
[Unit]
Description=BaleVPN userspace server
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/balevpn
UMask=0077
ExecStartPre=/bin/mkdir -p /root/balevpn/data
ExecStart=/root/balevpn/bale-vpn --headless --port 37127 --config-dir /root/balevpn/data server --nat-mode userspace
Restart=on-failure
RestartSec=5
KillSignal=SIGTERM
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
EOF
```

نمونه برای مسیر `/root/balevpn` و کاربر root همین راهنما است. برای اجرای بدون root، مسیر نصب، مالکیت داده و `User` سرویس را هماهنگ تغییر دهید؛ حالت userspace خودش به root نیاز ندارد. گزینهٔ `Restart=on-failure` برای راه‌اندازی دوباره پس از خطای پردازش است، نه پس از توقف عمدی با systemctl؛ [مستندات رسمی systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html#Restart=).

```bash
systemctl daemon-reload
systemctl enable --now balevpn
systemctl status balevpn --no-pager -l
journalctl -u balevpn -n 50 --no-pager
```

همان `--config-dir` قبلی حفظ می‌شود؛ اگر توکن معتبر باشد ورود دوباره لازم نیست. انتقال SSH همچنان روش دسترسی به پنل است. دستورهای مدیریت:

```bash
systemctl restart balevpn
systemctl stop balevpn
systemctl start balevpn
journalctl -u balevpn -f
```

برای اجرای systemd لاگ را از journal ببینید؛ `balevpn.log` مربوط به nohup قبلی الزاماً به‌روز نمی‌شود. Ctrl+C هنگام دنبال‌کردن journal فقط نمایش لاگ را متوقف می‌کند. برای لغو اجرای خودکار و توقف فعلی: `systemctl disable --now balevpn`.

## ۱۰. به‌روزرسانی و بازگشت

بستهٔ جدید را در پوشه‌ای جدا، مثلاً `/root/balevpn-update`، استخراج کنید. معماری، checksum و قابلیت اجرای فایل را پیش از جایگزینی بررسی کنید:

```bash
chmod +x /root/balevpn-update/bale-vpn
/root/balevpn-update/bale-vpn --version
```

برای نصب systemd، پس از آماده‌بودن فایل جدید:

```bash
systemctl stop balevpn
install -d -m 700 /root/balevpn-backup
cp -p /root/balevpn/bale-vpn /root/balevpn-backup/bale-vpn.before-update
if [ -f /root/balevpn/data/.bale-vpn_config.json ]; then
  cp -p /root/balevpn/data/.bale-vpn_config.json /root/balevpn-backup/config.before-update.json
fi
install -m 755 /root/balevpn-update/bale-vpn /root/balevpn/bale-vpn
systemctl start balevpn
systemctl status balevpn --no-pager -l
```

این نام‌های backup فقط آخرین نسخهٔ قبلی را نگه می‌دارند؛ برای چند نسخه نام جدا انتخاب کنید. backup تنظیمات هم توکن دارد و باید خصوصی بماند. پوشهٔ `data` را حذف نکنید و تنظیمات نمونه را روی فایل واقعی ننویسید.

برای بازگشت باینری قبلی:

```bash
systemctl stop balevpn
install -m 755 /root/balevpn-backup/bale-vpn.before-update /root/balevpn/bale-vpn
systemctl start balevpn
```

تنظیمات را بی‌دلیل از backup برنگردانید؛ ممکن است تغییرات جدید حساب یا فهرست مجاز از دست بروند. برای نصب nohup، ابتدا همان پردازش تأییدشده را متوقف و پس از جایگزینی، دستور اجرای اولیه را دوباره اجرا کنید.

در ویندوز پنجرهٔ قبلی را ببندید، فایل اجرایی/اجراکنندهٔ درست را جایگزین کنید و همان `data` یا `--config-dir` قبلی را نگه دارید. اگر چند پوشهٔ تست دارید، build-info و مسیر اجراکننده را تطبیق دهید؛ اجرای یک exe قدیمی در پوشهٔ دیگر، به‌روزرسانی محسوب نمی‌شود.

## ۱۱. رفع خطاها

در ساخت‌های جدید، حالت Server مجوز تماس حساب بله را خودکار روی «همه» تنظیم می‌کند و دوباره از بله می‌خواند. در پنل، عبارت `Bale incoming calls: Everyone (verified)` تأیید موفقیت است. اگر بررسی خطا داد، دکمهٔ `Allow Bale calls and recheck` را بزنید یا در بلهٔ رسمی، تنظیمات حریم خصوصی ← تماس را روی «همه» قرار دهید. این تغییر روی خود حساب و دستگاه‌های دیگر آن هم اعمال می‌شود و پس از بستن برنامه باقی می‌ماند. حساب Client و سایر تنظیمات حریم خصوصی تغییر نمی‌کنند؛ تأیید درخواست‌های تونل در خود پروژه همچنان لازم است. برای قابلیت خودکار باید فایل سرور هم به‌روز شود. [جزئیات و تست‌های مجوز تماس](call-privacy.md).

| نشانه | اقدام |
| --- | --- |
| `Permission denied` در اجرای لینوکس | chmod اجرا، دسترسی مسیر و mount دارای `noexec` را بررسی کنید. |
| `Exec format error` | خروجی `uname -m` را با `file ./bale-vpn` تطبیق دهید. |
| `GLIBC_… not found` | خروجی مناسب glibc سرور یا محیط سازگار لازم است. |
| خطای کتابخانهٔ گرافیکی/نمایشگر | خروجی headless و گزینهٔ `--headless` را استفاده کنید. |
| پورت محلی SSH اشغال است | انتقال قبلی یا برنامهٔ اشغال‌کنندهٔ `37127` را پیدا کنید؛ یک انتقال کافی است. |
| پنل سرور باز نمی‌شود | اجرای سرور، لاگ، شنوندهٔ loopback و بازبودن پنجرهٔ انتقال SSH روی **ویندوز** را بررسی کنید. |
| `403 Forbidden` از پنل محلی | از نشانی loopback و Origin همان پنل استفاده کنید؛ IP عمومی یا وب‌سایت واسط مناسب نیست. |
| خطای `set-cookie` بعد از Verify | بستهٔ قدیمی را بررسی کنید؛ کد اصلاح‌شده GET جداگانه به آن مسیر ندارد. بیلد صحیح و کد تازه لازم است. |
| `PHONE_CODE_EXPIRED` | کد تازهٔ همان درخواست لازم است؛ تا پایان مهلت درخواست مجدد صبر کنید. |
| `PHONE_CODE_INVALID` | تازه‌ترین کد همین درخواست را بررسی کنید؛ کد حساب یا درخواست دیگری را وارد نکنید. |
| `CallNotApproved` یا `StartCall: RPC error code=7` | این رد شدن از سرویس تماس بله است و قبل از رسیدن به Pending requests پروژه رخ می‌دهد. ابتدا تماس صوتی از حساب کلاینت به حساب سرور را در برنامهٔ رسمی بله امتحان کنید. اگر همان‌جا هم رد شد، مجوز تماس و محدودیت حساب‌ها را بررسی کنید؛ اگر تماس رسمی برقرار شد، قالب درخواست برنامه نیاز به بررسی بیشتر دارد. صرف این خطا علت دقیق رد شدن را مشخص نمی‌کند. |
| بعد از Connect دوباره همان دکمه دیده می‌شود و خطایی نیست | در ساخت‌های قدیمی، خطای تلاش اتصال هنگام پاک‌سازی نشست از صفحه ناپدید می‌شد. ساخت اصلاح‌شده خطا را در `clientError` نگه می‌دارد و تا تلاش بعدی، قطع اتصال یا خروج نشان می‌دهد. سبز بودن WebSocket به معنی برقرار شدن تونل نیست. |
| `persist … os error 3` یا نبودن مسیر data | بیلد اصلاح‌شدهٔ ساخت پوشهٔ تنظیمات و مسیر قابل نوشتن لازم است. ساخت دستی پوشه راهکار موقت است. |
| فقط عنوان Tunnel proxy و Logout دیده می‌شود | عنوان دکمه نیست؛ بیلد اصلاح رابط را اجرا کنید. بارگذاری تازه در مرورگر راهکار موقت است. |
| فقط WebSocket متصل است | peer سرور را انتخاب کنید، تونل را برقرار و پراکسی برنامهٔ مصرف‌کننده را تنظیم کنید. |
| حساب سرور در فهرست نیست | Refresh، جست‌وجوی شماره و انتخاب نتیجهٔ درست را بررسی کنید. |
| اتصال رد می‌شود یا منتظر سرور می‌ماند | آنلاین‌بودن سرور، درخواست پذیرش، Allowed callers، Blocked callers و ظرفیت سرور را بررسی کنید. |
| Connect دوباره ظاهر می‌شود | تلاش ممکن است شکست خورده و peer پاک شده باشد؛ علت را رفع و سرور را دوباره انتخاب کنید. |
| مرورگر مستقیم وصل می‌شود | تنظیم SOCKS5 همان مرورگر/برنامه را بررسی کنید؛ تمام سیستم خودکار پراکسی نمی‌شود. |
| دامنه‌ها باز نمی‌شوند | Remote DNS یا `socks5h`، سپس DNS و اینترنت خود سرور را بررسی کنید. |
| پورت 1080 بسته است | آماده‌شدن واقعی تونل و پورت انتخاب‌شده را بررسی کنید؛ توکن یا WebSocket کافی نیست. |
| سرویس مرتب restart می‌شود | journal، مسیر فایل، مجوز اجرا، glibc و اشغال‌بودن پورت را بررسی کنید. |

برای گزارش، متن خطا، نقش دو سمت، سیستم‌عامل/معماری، روش اجرا و شناسهٔ ساخت را بفرستید. شمارهٔ کامل، کد ورود، توکن، فایل تنظیمات و لاگ بررسی‌نشده را منتشر نکنید؛ این اطلاعات را در تصویر هم بپوشانید.

## ۱۲. قطع اتصال و چک‌لیست آزمون نهایی

- Disconnect کلاینت تونل را قطع می‌کند. برای توقف اجرای مستقیم برنامه، پنجره/پردازش آن را ببندید؛ برای سرور systemd از `systemctl stop balevpn` استفاده کنید.
- Logout توکن ذخیره‌شده را پاک می‌کند؛ برای توقف موقت سرور یا بستن پنل نیازی به Logout نیست.
- پس از قطع تونل، تنظیم پراکسی مرورگر ممکن است فعال بماند؛ برای اینترنت مستقیم آن را غیرفعال کنید.
- پاسخ HTTPS از SOCKS، IP خروجی، اتصال مجدد پس از Disconnect/Connect، و حفظ تنظیمات پس از restart سرور را جداگانه بررسی کنید.

تست‌های ساخت، رابط و پروتکل جای آزمون زندهٔ دو حساب را نمی‌گیرند. سرعت و پایداری به شبکهٔ دو سمت و زیرساخت بله وابسته است. برای مدل امنیتی، محدودیت رمزنگاری raw IP و احراز هویت peer در QUIC، [توضیحات امنیتی پروژه](../README.md) و [گزارش آزمون‌های امنیتی](security-testing.md) را بخوانید.

راهنماهای مرتبط: [Rust](rust-fa.md)، [ورود و دریافت کد](auth-protocol.md)، [اتصال و بازیابی](connection-performance.md)، [اندروید](android-fa.md).


برای بسته‌های گرافیکی ۲٫۶ و انتقال نشست بدون درخواست کد تازه، [راهنمای دسکتاپ و انتقال نشست‌ها](desktop-session-transfer-fa.md) را بخوانید.
