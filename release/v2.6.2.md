# BaleVPN 2.6.2

Security update for Windows, Linux, macOS (Apple Silicon and Intel), and Android.

The WebRTC/DTLS dependency chain now uses crypto-bigint 0.7.7, p256/p384 0.14 and elliptic-curve 0.14.2, removing RUSTSEC-2026-0387. The bounded DTLS compatibility patch preserves the wire protocol and record ciphers. DTLS tests include P-256/P-384 interoperability with ring, invalid-point rejection and repeated key agreement. The data transfer pipeline is unchanged; this update does not promise a higher download speed.

Compared with the previous public release, desktop builds also include authenticated QUIC pairing, protected local sessions, encrypted session transfer, multiple account profiles, optional automatic reconnection, traffic charts, Persian/English localization, themes, and native window/tray controls. Reconnection is off by default; when enabled it retries after unexpected or manual disconnection. Multi-tunnel mode distributes separate TCP connections and does not combine a single TCP stream.

## Downloads and upgrade

- Windows: extract `BaleVPN-desktop-windows-x86_64.zip`, then open `BaleVPN.exe` (WebView2 runtime required).
- Linux desktop: extract `BaleVPN-desktop-linux-x86_64.zip`; install GTK3, WebKitGTK 4.1 and Ayatana AppIndicator runtime dependencies. Run `install-desktop.sh` for an application-menu launcher.
- Linux VPS: use `BaleVPN-headless-linux-x86_64.zip` (glibc 2.35+, for example Ubuntu 22.04+ or Debian 12+). `start-client.sh` explicitly starts a client on management port 37128; `start-server.sh` starts a server on 37127. Access the loopback panel through SSH forwarding.
- macOS: choose `macos-aarch64` for Apple Silicon or `macos-x86_64` for Intel. The desktop ZIP contains `BaleVPN.app`; headless ZIPs are separate. These builds have no Apple Developer ID signature or notarization.
- Android: install `BaleVpn-2.6.2-release.apk` (Android 7+, ARM64/ARMv7). `BaleVpn-release.apk` is an identical stable-name copy. There is no iOS build in this repository.

Stop the previous desktop process and retain its data directory when upgrading. Existing valid desktop sessions and pairing keys are retained. Do not remove account data to resolve an installation issue. Full Persian setup, session transfer, reconnect and troubleshooting guides are included in every native ZIP.

Android now uses a persistent release signing key rather than a runner-generated debug key. Older APKs signed by another key cannot be upgraded in place; Android rejects that signature change. Back up any needed data before considering removal of an old installation. This update cannot recover the old signing key or bypass Android's signature protection.

## Verification and limits

Publication is gated on successful tests and builds on all four desktop runner targets, Android APK signature/version/ABI checks, audits of all six Rust lockfiles and source secret scanning. `security-evidence.zip` contains the dependency audit results. ZIPs include `build-info.json`, full internal checksums and upstream DTLS licenses; the release-level `SHA256SUMS.txt` covers downloadable assets.

The fixed dependency does not make Bale calls anonymous: the provider can observe accounts, IPs, call timing and volume. Android's existing unpaired/raw-IP path does not provide the desktop paired QUIC authentication guarantees. No real-account Bale call, sustained internet throughput, physical Android device, or interactive macOS GUI test is claimed by CI. Local isolated Windows/Linux GUI checks are reported separately with the test builds.
